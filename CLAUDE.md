## Project overview

Working-time recording: employees record when they came, when they left and how long their breaks were —
as an entry form or with stamp-clock buttons. One offline HTML file (React/Vite singlefile), data only on
the device. Created 2026-11-23.

**Stages (Tobias, 2026-11-23):**

1. **Stage 1 (now):** record locally; store encrypted in `local-vault`; navigation with `rad-navi`;
   a backup file everyone can make; at the end of the month a summary as **PDF with an attached JSON file**, which the
   employee mails himself/herself to the digital personnel file. **No `device-sync`, no Treffpunkt.**
2. **Later:** sync between devices with `device-sync` over a **configurable Treffpunkt** (a second one for
   the Kanzlei is possible), so that the person responsible for personnel sees the times; handing the data
   from an old device of that person to a new one; a separate base repo that fetches trusted timestamps
   from free (later also paid) time servers.

**Platform:** web (browser, installable later as PWA)
**Language:** TypeScript + React 19
**Architecture:** UI-free logic layer `src/logic/` (data model, rules, stamp clock, summary, report, backup,
retention; clock and "now" are parameters, errors are codes) and a thin UI `src/ui/`. The logic runs and is
tested without any UI. Private companion repo: `Zeiterfassung-privat` (data only).

  `*.zeiterfassung.json`).
- Dependencies `local-vault` (tag `v0.1.0`) and `rad-navi` (tag `v0.1.1`) come by Git tag; their install
  scripts build them (`prepare`). Tags are changed only with Tobias' OK.
- **Zeitstempel library (TEMPORARY pin):** `zeitstempel` is pinned to commit `c50a72e` (its `main` after PR #11:
  one client `zeitstempel/client`, relay auth v3, evidence v1, trust per service, `verifyEvidence` takes the whole map; built on install by its `prepare`)
  until the PC pushes the approved tag `v0.2.0` on that commit (then switch to `#v0.2.0`). The app uses `createRelayClient` from
  `zeitstempel/client` through the thin adapter `src/io/anchorService.ts` (German texts stay in the app; timeout
  130 s; no `GET /v1/services`: services and trust come from the package's `services.json`/`anchors`). **Audience**
  from the build variable `VITE_TIMESTAMP_AUDIENCE` (default: the relay origin). **Every stamp `mode: 'solo'`**; the
  running PDF takes only `kind: 'single'` evidence (a batched token stamps the batch root, not the PDF digest).
- **Device key (decision Tobias 2026-11-25):** one key per device; a device is unlocked by pasting
  `<kid>.<private key>` (`make-key --solo` of `zeitstempel`) in the settings; imported as a non-extractable P-256
  CryptoKey kept in IndexedDB `zeiterfassung-geraeteschluessel` (`src/io/keyStore.ts`); the vault slot `geraeteschluessel`
  holds only `kid:<kennung>`; the pasted text is never stored (an old text slot is migrated once on load); never in
  the backup; only the kid is shown. Without a key: „Gerät nicht freigeschaltet“; recording times always works. Keys are created in
  the project for now (`docs/geraeteschluessel.md`); a key server may follow.
- **`pdf-fortschreiben` is pinned to commit `7148b7b`** (TEMPORARY; its `main` after PR #4: hardening series,
  entry `pdf-fortschreiben/pdflib`, version 0.1.0, `dist` built on install by its `prepare`) until the PC pushes the
  approved tag `v0.1.0` on that commit (then switch to `github:tobiasheinrichfaska/pdf-fortschreiben#v0.1.0`).
- **Running monthly PDF (decided 2026-11-24; built, never run in a browser):** one PDF per month, continued
  with `pdf-fortschreiben`; each **ended** day (with „Gehen“, not after today) is appended as **a new page**
  (table up to that day) plus **a new JSON attachment with its own name** (add only), then one document time
  stamp over the new state (reserve 8192 bytes, once more with 16384 on overflow). `RunningPdfProvider` runs at
  start, when an ended day is missing, when the relay changes and every 15 minutes while unstamped; one run
  at a time; the unstamped state is kept and shown on failure. The stamp chain and `anchors` **both stay**.
  Free services first (qualified later, only in the relay). A day reopened after it was appended shows its
  later state only on the next day's page; **a correction after the month's last day page (the last day of the
  month, or any day once no later day follows) never reaches that month's running PDF** (only the export PDF
  of the month shows it; not fixed, 2026-11-27). A run is also due when none finished yet or the last plan is
  of an earlier month (`runningPdfDue`). Within the first week of a month the previous month's „gespeichert“
  marker is never overwritten (the current month waits instead; else that month was started again).
- **Base library `pdf-fortschreiben`** (incremental PDF revisions, PDF/A-3 attachments, PAdES document time
  stamps) lives in its own repository `tobiasheinrichfaska/pdf-fortschreiben` (extracted 2026-11-24 with its
  history). The app uses it by the commit pin above: `src/logic/runningPdf.ts` draws each day page through
  `prepareDrawnPages`/`reuseFont` of `pdf-fortschreiben/pdflib` (no own copy of the pdf-lib hybrid code), adds the
  attachment to the same revision and writes it with `writeUpdate`; `src/io/runningPdfWork.ts` stamps with
  `appendDocTimeStamp` (the token must be one DER SEQUENCE). Each revision gets a new second `/ID` element.
  After the re-pin (2026-11-26, `e2e/` with zeitstempel `c50a72e`): running PDF 53/53, `pdfcheck.ts` 9/9 on the
  three running PDFs of that run (`stamping.cjs` not rerun).
- **Base library in a subdirectory (TEMPORARY):** `einzeldatei-csp/` (Content-Security-Policy for an offline single file: inline script hashes, `connect-src` from origins, `checkCsp`, Vite plugin) has its own `package.json`, tests and CI job (`einzeldatei-csp` in `tests.yml`); the app does **not** use it yet (same default policy as `src/build/csp.ts`). It lives here only because the cloud session could not create a repository. **Claude on the PC: extract it next time, following `einzeldatei-csp/HERAUSLOESEN.md`.** Root lint and format ignore it.
- The device clock is not a trusted time: `recordedAt` and the stamped minutes are what the device says.
- Retention: only a month that was **exported** may be purged, and never a running day.

## Data Model

Authoritative reference: [`docs/data-model.html`](docs/data-model.html). Regenerate/align it in the same
session the model changes.

Decisions behind it: times are minutes since local midnight of the arrival day (wall clock, no time zone,
so daylight-saving changes need no special case; a shift past midnight has `endMin` above 1440); one
working day per date; a pause is a length or a span; at most one running day; backup and the stored book
are the same format (version 3; versions 1 and 2 are read and migrated without loss).

Measured: ~24–25 KB per stamped day. Not covered: MT-35, MT-36, three months, the share sheet, a PDF viewer. **Still unchecked:** real phones (real finger gestures, on-screen keyboard, the share sheet and „PDF teilen …“, the look of the PDF in a viewer, PDF/A validation), other browsers (Firefox, Safari), **any real time stamping service and a deployed relay** (nothing real was contacted), a real build with the real trust anchors in a browser (the real anchors are covered by unit tests with a recorded real FreeTSA token, not by the browser run), MT-27 (backup with chain) and MT-28 (full chain; unit tests only), and the whole stage as used by real people for a month.
- The PDF holds the readable table, the logged changes of the month and the monthly data as an **attached JSON file** (`zeiterfassung-JJJJ-MM.json`, canonical form) that only confirms the table (decision 2026-11-23); its SHA-256 is printed in the PDF. **XML can be added later if the personnel file demands it** (the earlier XML code was removed). Whether the personnel file accepts attachments is not checked.
- **PDF/A-3b: built to the standard, NOT validated.** Embedded fonts, XMP with `pdfaid` part 3 / conformance B, sRGB output intent with a profile generated in code, document ID, attachment as associated file with `AFRelationship Data`, no encryption, no scripts, DeviceRGB only — checked by structure tests of the written file (`tests/pdfa.test.ts`). No PDF/A checker (veraPDF needs Java; none installed) has been run: **say „nach PDF/A-3b gebaut, nicht validiert“, never „konform“**, until Tobias has a validator report. The sRGB profile is our own generation, not validated by an ICC tool.
- **Characters:** the embedded font (Noto Sans, Latin subset) covers the German alphabet (a–z, Ä Ö Ü ä ö ü ß), digits, usual punctuation including „ “ – and €. Anything it lacks (emoji, arrows, other scripts) is replaced by „?“ **in the PDF table and the change texts** (`keepSupported`); the attached JSON keeps the real text.
- The built HTML is about 1.5 MB (pdf-lib, fontkit, two font files). Third-party material and licences: `third_party/`.
- **Content-Security-Policy** (meta tag, hash of the one inline script, `default-src 'none'`, `connect-src 'none'`, `style-src 'none'`, no workers/frames/objects/forms/base): built into the file by `vite.config.ts` (`src/build/csp.ts`). `tests/build/built.test.ts` builds the real file into `.tmp/` and checks the policy against it (hashes match, nothing loaded from outside, no `eval`/network code). **Not run in a browser**: that React's style props (CSSOM), the `blob:` download link, the share sheet, IndexedDB and WebCrypto raise no violation is expected but unverified (MT-22). `@pdf-lib/fontkit` carries the „function-bind“ fallback that would build a function from text; it is only reached where `Function.prototype.bind` is missing and could not run under this policy anyway.
- The backup file is **encrypted with a password by default** (PBKDF2-SHA-256, 600000 rounds → AES-256-GCM, header bound as authenticated data). An unencrypted file is possible only after an explicit choice and a warning; reading accepts both. A lost password cannot be recovered, and a wrong password cannot be told from a changed file. The password rule is only length (8 to 256 characters); no strength meter.
- **Time stamps (format 3).** Every finished write to a day is chained in `stamps` (SHA-256 over canonical JSON, gapless numbers, `prev`/`hash`, `skew` for a clock that went back) and every ended day gets one `seal`; the chain holds hashes, never times or notes, and **the internal times are the device clock: they prove no time**. Only `anchors` (tokens of an external time stamping service) prove one. **The app can meet „at the latest every 24 hours“ only while it is open and online**: a web page has no background; `overdue` is recognised, shown (month page, report) and not prevented. The pause after a 429 is measured on the monotonic clock (a device clock set back must not stretch it; a bug found in the second headless run). A relay sees the time and network address of a request, never any content (only a hash is sent). Free stamping services are not qualified. The relay protocol is the real one of the `zeitstempel` package (`docs/relay.md`); **no real stamping service and no deployed relay was ever used** (tested against a local relay with a test PKI, and the library's recorded real tokens, see below). The app verifies each token itself (hash, signature, certificate chain to the shipped anchors, certificate validity at the token's time) but, like the library, **not revocation, name constraints or policies** (`zeitstempel/docs/grenzen.md`); tokens read from a backup are not re-verified. An anchor stores the verified token's time and serial, not the relay's claims. The free services are not qualified; a relay's service list is a choice of the relay, the app takes the first service it has anchors for and tries up to three.
- Anchors need the build variable `VITE_TIMESTAMP_RELAY` (the page's policy then allows exactly those origins); without it the app cannot reach any service and says „Kein externer Zeitstempeldienst eingerichtet“. An address typed in later works only if it is one of the build's (the setting is a choice among them).
- The chain is limited (6000 stamps, about 6 per day ≈ 3 years in the browser's storage); a full chain **refuses new writes** with a message (sealing seals as many ended days as still fit, oldest first); purging shortens it only for months without days that an anchor covers (or when no relay is set). The stamp dates and hashes of purged months stay (no times, no notes). The change log and the chain are **not tamper-proof against someone who holds the unlocked device** (they can rewrite everything and recompute the hashes); only an anchor made before that proves the earlier state.
- Real-time stamp actions (Kommen, Pause, Gehen) are not in the change log (decision) but are in the stamp chain.
- The page the wheels were on is remembered in the browser's plain storage (key `ze-seite`, only the page's node id); when the storage is blocked the wheels start on the first page. A form being typed is kept in memory and, encrypted, in the vault slot `draft` (survives swiping away and closing the app; removed on saving or discarding); a draft that does not pass the strict reader is dropped silently.
- The app lock texts come from `local-vault` (German texts passed in `src/ui/vault.ts`).
- **Running monthly PDF storage (decision Tobias 2026-11-24, never run in a browser):** PDFs are kept

- One working day per date: a split shift (morning and evening) cannot be recorded as two shifts; use one
  day with a long pause.
- The stamp clock trusts the device clock. Nothing proves the time (a later stage adds timestamps from a
  time server).
- A lost device loses everything not backed up or mailed; there is no server copy by design.
- E-mailing the PDF is done by the employee by hand (a browser cannot attach a file to a `mailto:` link).
- The default retention of 24 months is a starting value, not a legal ruling.
